## 同一个输入框：暗手 + 固定面子

| 写法 | 定义 |
|---|---|
| `233m [p]` | 暗手含233；至少有一个碰 |
| `x{11} [c]` | 暗手11张，至少一组吃 |
| `[999]` | 一门数牌的九刻，不隐含哪个花色 |
| `[999s]` | 九索刻子，仍随全手花色变换 |
| `[c:456s@6s]` | 吃456s，明确鸣入的是6s |
| `[a]` / `[d]` / `[kakan]` | 暗杠／大明杠／加杠 |
| `[k]` / `[*]` | 任一种杠／任一种固定面子 |

`[p]`里的p是碰类型，不是筒花色。裸数字暗手（如123）是查询万子的简写；明确多花色仍用m/p/s/z。方括号无顺序，每个槽匹配不同的固定面子。默认 `meld_mode=contains`；`exact` 要求全部固定面子恰好对应，无方括号且exact表示无固定面子。

暗手、固定面子、鸣入牌、赤牌、宝牌位置及损存必须由同一变换同时满足。没有独立移动某副露或把两种字牌合成同一刻子的捷径。一个杠仍占三个结构位，但供给计数是四张实体牌。

`111234565678 [999]` 是12张暗手+一副露，切牌前共15个结构位，属于非法输入；程序会提示一副露暗手最多11张，而不默默删一张。可用 `123m345p678s11z [999m]` 作合法14结构位示例。

## 真实牌河虚影与鸣牌配对

每次明鸣记录来源弃牌的原始事件号、河内第几张、来源座位和稳定call_id。在原河位保留虚影，与整组副露使用同色边框/底色和同一C编号；悬停或键盘聚焦可同时突出。配色循环使用青绿、紫、赭黄、蓝、珊瑚、草绿，另有编号和虚线，不仅靠颜色，也不把所有鸣牌涂成容易混淆立直的红色。

加杠是新动作事件，但沿用原碰的来源call_id和颜色；不会虚构第二张被鸣走的河牌。暗杠无他家来源虚影。全部来源只来自当时已发生的事件，较早快照不显示以后才鸣走的标记。切牌本身与搜索归一化不修改真实来源关系。

## 两个鸣牌索引及分母

`research.sqlite` 增加 `call_events` 和 `call_opportunities`，原始切牌行不变：

- 真实事件：一次吃/碰/大明杠/暗杠/加杠是一行，包含来源与前后暗手；不把之后十次切牌算成十次鸣牌。
- 机会：他家一次弃牌或自己一次摸牌，确实存在至少一个规则允许的鸣牌/杠候选才是一行；同次两个吃法、赤/普通组合不增加分母。

枚举检查来源方向、实体牌供给、喰替后的合法弃牌、已立直限制、牌山末端、总杠数上限；立直暗杠需新摸入第四张、不送杠、待牌种类保持。只因分解或役种改变不否决天凤允许的暗杠。杠后的指标停在岭上摸牌前，不用后来摸牌或新增宝牌评价之前决定。

结果标签：`selected` 已登记所选候选；`not_selected` 正常继续而未登记鸣牌；`chose_win` 自己选择和牌；`censored` 他家鸣牌/和牌或终局导致无法证明主动不鸣。自动不鸣设置和客户端对赤牌组合的控制不在XML中，不假称已观测人类主观选择。

查询类型为chi时，该机会可能最后选择pon。状态计数的selected包含其他鸣法，`choice_counts`另列所查询类型与其他动作。接受率分母只用有明确响应的selected+not_selected，不含删失/和牌；按outcome筛选后不再返回有误导性的“选择率”。

```text
GET /api/research/opportunities?trigger=external&call_kind=chi&limit=20
GET /api/research/opportunities?trigger=self_draw&call_kind=ankan
GET /api/research/call-events?call_kind=kakan&actor_relative=0
```

机会查询中的暗手和`[p]`指行动**之前**的状态，`offered=6s`与其共享映射。当前没有实现任意复杂的“候选副露后牌形”查询语言；可读取每个候选的消耗牌、鸣后暗手、合法切牌集合和最低切后向听。

网页有独立机会查询区，MCP新增 `luckyj_opportunities`、`luckyj_call_events`；先读schema定义。接口完整计算统计后才分页，超时不返回扫描前缀冒充全量。

## 如果和牌：条件价值，而不是最后实际和了什么

只给**实际切后已听牌**的状态逐待牌枚举，分别荣和/自摸、赤五/普通五，计算最高合法计分分解的役、番、符。未听牌返回not_tenpai，因为未来补完路线不唯一；不是零番。

使用当前真实门清/副露、自风/场风、已成立或本次已声明立直、当前已知指示牌。不假设未来新立直、里宝牌、新杠宝、一发、海底/河底、岭上/抢杠。保留结构上有但存量为0的待牌；查询默认只接受存量正的条件和牌。

`win_yaku=平和,门清自摸` 要求同一待牌、同一和牌方式的结果同时具备二者；不是不同待牌各有一个就拼起来。泛称立直包括双立直，国士/四暗刻/九莲查询包括相应双役满变体。`win_han_basis=total|yaku` 决定含不含宝牌。役满独立使用倍数，不把它伪装成普通13番。

```text
/api/research/search?win_yaku=平和&win_method=tsumo&win_han_min=3
/api/research/search?win_yaku=役牌&win_han_basis=yaku&win_han_min=2
/api/research/search?win_yakuman_min=1
```

这仍是“若以该完成形和牌”的价值，不是和牌率，也不是完整荣和权限判定。永久振听单独标记（含被鸣走的自身弃牌和当前切牌）；临时振听尚未计算。结果中保留永久振听的荣和计分供条件比较，不能将它理解为当前可合法荣和；界面及配方显示这个限制。新役番筛选不会读取本局最后的AGARI。

## 弃和／兜牌：有依据的假说，不是标签真值

模型 `models/intent-v1.json` 是显式专家参数的三状态HMM：push（进攻）、mawashi（回避但保留和牌）、fold（弃和）。各手先枚举合法弃牌，比较实际选择与最快候选的向听差、真实存量加权的进张损失及相对安全性，再结合时序。没有“退向听就直接等于弃和”的规则。

安全性使用现物、立直后已通过牌、字牌可见张数、弱筋信息；对多个威胁同时比较，筋绝不当作绝对安全牌。威胁来自他家已立直或三组明副露（后者明示为代理）。一两副露默听、隐蔽进攻和许多读牌细节未覆盖。

相关证据聚成一个联合类别，避免“退向听”“牌效损失”“跟切安全牌”被当作三个独立证据重复相乘。比如重大牌效牺牲且安全性改善的似然列为push0.01、mawashi0.04、fold0.39；保持最快路线同时选明显更安全牌，更支持mawashi。它们是公开的专家假设，不是从LuckyJ标注频数拟合来的数字。

贝叶斯更新：`posterior_t ∝ likelihood(category_t | state_t)^(1/temperature) × prior_t`。先验由上一手后验经转移矩阵推进，并以context_reset部分混入当前威胁背景。温度1.35压低过强似然，减少过度自信；参数和每次贡献均可检查和修改。

- **当手online**：只用当前和过去事件，追加未来牌谱不会改变它。
- **复盘review**：有限向后平滑，最多参考随后3次自己的切牌，明确列出未来证据事件号。它不是当时可用的信息，不可拿来当先验或在线预测输入。
- 立直后受限动作、只有一种合法牌种等不按主动押引分类。证据不足显示uncertain。每种状态仍有模型后验，但`calibrated_probability=null`。
- 默认阈值0.62只是显示阈值；`intent_state=fold&intent_min=80`筛的是模型内部后验≥0.8，不是“准确率80%”。状态筛选按后验，不要求系统已给出确定标签；可能包含依赖先验较多、显示仍不确定的记录。
- 先验fold权重减半/翻倍及温度变化的敏感度包络可检查；不是可信区间或经验置信区间。

不同状态可以转回进攻；兜听通常需要检查连续几手和恢复听牌轨迹。本版本只给兜牌倾向与可审查的轨迹，不宣称已经识别所有人类定义的兜听。点况、役价值、非立直威胁的精细估值目前保留作证据背景，**尚未给它们拟合或手调权重**。牌效牺牲也可能为手役或打点，不应当作必然弃和。

模型参数可通过 `python -m luckyj enrich --intent-model models/my-model.json` 改变，哈希写入报告和查询配方，旧模型后验不混入新模型。

## 人工复核、校准与下一轮策略规则

详情可以选择人工标签、写理由并下载一条复核记录，不自动写进模型。看过模型预测的记录标记为已展示，便于识别锚定偏差。详情面板展示了后续复盘信息，因此导出的标签明确记为review，不混入online评价；需要用 `--mode review` 评估。更适合在线校准的是先盲标：

```sh
python scripts/intent_review.py export --data data --output labels.jsonl --limit 200
# 人工填写 human_label / human_comment / labeler，不用模型预测填充标签
python scripts/intent_review.py evaluate --data data --labels labels.jsonl --output evaluation.json --fit-temperature
```

同一对局的状态按游戏ID哈希一起分到训练或测试组，不把同一局的相邻步骤分到两边。只在训练组选择温度，测试组报告logloss、Brier分数和可靠性分箱。少于20个训练标签或缺类别时不拟合；输出独立候选校准器，不悄悄替换上线模型。文件以独占创建，避免覆盖人类标签。

目前**没有人工标签、没有测试集准确率或校准结果**。不能把伪标签当证据证明自己的规则正确。下一轮提供的策略总结应先成为有适用范围的规则假说，与模型原有信号检查重叠；独立人工判断才用于检验与校准，避免循环论证。

本轮本地全库：1,256场、156,324个决策；41,236个有候选的鸣牌/杠机会，其中已选择7,457、正常继续未鸣32,249、删失1,019、自己和牌511。7,457个选择事件与原始XML的目标N事件逐事件一致。条件听牌价值计算25,218手，产生97,342个逐牌/荣和/自摸组合（含无役或零存量项）。这不是25,218次真实和牌。

全库配对153,630个“快照中已固定明面子”引用与真实河位/实体牌一致；同一副露在之后多手重复引用，所以不是153,630次鸣牌。HMM后验归一化与未来标记已核对，**不是模型准确性验证**。详见 `calls-intent-audit.json`。

本地浏览器环境阻断网络导航，因此本地截图采用DOM+真实HTTP API桥接，未声称验证本地浏览器网络/CSP。GitHub CI使用不带bridge的Chromium直连HTTP验收，最终结果看PR检查。原始数据文件和schema不改写，数据/研究缓存不提交Git，不上线公网。
