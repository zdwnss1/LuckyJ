# 牌形研究室：同形、损存、候选牌理与 LLM 统计

本轮在 `main@6831499` 上增量开发，沿用 `luckyj/` 模块、同一份原谱和第一阶段 SQLite。不是第四套独立应用，不合并 `phase1-database` 或 `phase1-query-db`。旧检索和 API 保持可用，新入口为 `/research`。

## 启动

需要 Python 3.10+。使用 **main 的正式数据包** `phase1-data-35350863730` 中的 `data/`，不是 PR #2 的同名 ZIP；两者 SQLite schema 不兼容。

```sh
python -m luckyj enrich --data data
python -m luckyj serve --data data
# 浏览器：http://127.0.0.1:8000/research
```

`enrich` 不请求源站，不改写原始 SQLite。生成原子替换的 `data/research.sqlite`，绑定原库 SHA-256。原库更新后必须重新 enrich，不能混用新旧索引。语料缺口仍是来源无 URL 的65条，不能当作已补齐。

默认纯 Python。大量牌理计算可选用本机 C 编译器构建附带源码的加速器：

```sh
python -m luckyj native
# 或首次 python -m luckyj enrich --data data --native
```

无本地编译器也能运行；Windows 默认用 Python。项目不下载不透明二进制。`LUCKYJ_PURE_PYTHON=1` 强制回退。

## 一个输入框，同时表达精确和模糊

- 空或 `*`：不限制手牌，只筛场况、向听等。
- `233m`：包含一张二万和两张三万，未写的牌不限。
- `x{12}77z` 与 `xxxxxxxxxxxx77z`：十二个任意牌槽，加同一种字牌两张。
- `111234556789m(1-5p)(1-3s)`：十二张固定牌和两个单张范围槽。
- `(1m|4p|7z)`：列举候选的一张牌，不是三张。

写满当前暗手张数即完整匹配；没有“模糊/精确”按钮。每个槽消耗一张独立的牌，重叠范围通过容量匹配，不会用一张二万同时满足两个槽。最多十四张暗手，固定面子不含在暗手条件内。已有 `77z` 不等于恰好只有两张，其他任意槽仍可能容纳第三张。

## 对称自由度，与真实筛选分开

默认换花色、默认关闭数字反转，不提供数字平移。同一门必须整体变换，选择反转后可以每门独立 `1↔9 … 4↔6`。字牌采用身份一一重命名，默认保留0非役/1单役/2双风。角色以 LuckyJ 的真实场风和自风计算；查询字牌槽的角色可编辑，默认七槽为 `1,0,0,0,1,1,1`，界面明确展示，不把“东永远是役牌”当作规则。

例如东场北家真实 `2z5z`，可映射至查询 `1z3z`：白→单役的查询1z、南→非役的查询3z。两种不同字牌不能合成一个对子，同一种字牌也不能拆成两个身份。未锚定字牌的显示补全仅供排列，统计保留“非役字（未锚定）”等类别。

赤牌位置默认不区分，但显式 `0m` 始终要求赤五。宝牌位置是对应牌种的宝牌重数，不是机械映射指示牌。宝牌数量和赤牌数量是独立筛选，计入自己的固定面子；不读未来指示牌和里宝牌。

手牌、摸切条件、损存和宝牌位置必须由**同一个变换同时满足**。多种变换满足同一记录时只计一次。无法唯一对齐的动作保留联合桶，例如 `3m / 7m`，不按实际切牌挑一个方便的方向，也不分数复制样本。

单个结果卡可独立切换原样/同形，连同展开的进张牌名一起改变；数值和全局分母不变。详情牌桌始终为真实状态，同形对照另置，避免伪造宝牌指示关系。

## 逐牌损存

`7m-2` 表示暗手之外已见两张七万；`8m+1` 表示扣除暗手与公开牌之后八万剩一张。可单独输入，无须先画整副手牌。范围：`7m-[1..2] 8m+[0..1]`。

```text
存(t) = 4 - 自己当前暗手(t) - 去重公开牌(t)
```

公开牌包括所有牌河、四家固定面子和已公开指示牌。被鸣走的同一张牌不能扣两次。34种牌总量合并赤五；37槽另保留赤/普通五供给。这里的“山存”是当前信息下未见数，不是全知活牌山：未知的对手手牌不会被偷看扣除。

只约束写出的牌，不锁死整个剩余向量。条件跟随搜索映射。`+`不是加牌，`-`不是修改手牌，查询绝不改造事实。切出一张后它进入已知牌河，不能重新算成可摸张数。

## 向听与全部合法候选

保存配牌、摸牌前、当前、实际切后、合法候选最低切后五个时点。鸣牌后没有本次摸牌，摸牌前值为 null。0=听牌，-1=完成形；普通形/七对子/国士取合法最小值。有固定面子时不误算特殊形。

每条结果即时计算实际切牌的逐牌进张，详情计算所有合法切牌候选。手切/摸切按原谱实体ID，候选按牌种区分赤五。候选合法性包括鸣牌后喰替和已成立立直只能摸切；若已宣言本次立直，则保留能进入听牌的切法。

普通结构向听不因为牌河见光就偷偷变成另一种定义。有效进张先求能降向听的牌种，再按当前真实存量加权；零存量入口灰显，不贡献张数。它是结构进张，不声称存在役、可以荣和或不振听，更不是EV建议。

最大进张：先限定最低切后向听，再比较有效进张总张数。并列最大全部标记，返回并列数；最大好形独立比较。结果页只计算实际动作时不假装已比较全部候选，最大字段为 null。使用相应筛选或打开详情会做完整比较。

### 好形指标：shortest-ryanmen-v1

一向听：某种进张后存在一种弃牌能进入两面听牌，该进张算好形。听牌时按可拆成两面待牌的和牌入口计数。更高向听：存在严格逐次降向听的最短结构路线，到达两面听牌。多解形只要存在符合的分解即成立，不把七对子单骑当成两面。

**当前这一步的权重使用真实损存；后续路线是结构可达性，不是未来摸牌概率，也不做多步真实山牌资源消耗模拟。**这一定义和“立刻进入两面听牌”“改善但不降向听的好变张”不等价，后者尚未作为第二套指标实现。

每次计算有明确证明节点预算。未决项返回 null 和上下界，不当作0或false。涉及未决好形的精确筛选返回错误而非部分统计。可提高预算并预计算：

```sh
python -m luckyj precompute --data data --query examples/early.json --all-candidates --good-budget 50000
python -m luckyj serve --data data --good-budget 50000
```

缓存 `research-metrics.sqlite` 与原库/研究事实库分开，按快照、算法版本、计算范围和预算键控。先用不含效率条件的配方预热再查询。大量全库候选计算可能较慢，不能把建好事实索引称作所有反事实指标已经预计算完毕。

## 场况、比较与分母

早/中/晚是 LuckyJ 第1—6、7—12、13+次切牌，含鸣牌后的切牌，不是严格全桌巡数。支持具体区间、四家分数/次位、当前点差、立直人数、宝牌数量、向听时点等。默认排除自己已成立立直后的后续摸切，但保留宣言当次。

点差字段始终是切牌前；分数/次位可以切换局初。没有上位或下位时相应点差为 null。比如自己一位时“距上一位≤8000”不会自动命中。

研究比较有两种可组合的可执行动作谓词，不接受任意SQL或代码：

1. `follow_honor`：本次之前、上次 LuckyJ 弃牌之后，他家切过的同种真实字牌；角色和是否单张可选。不是“同属非役牌就叫跟切”，也不声称因果。
2. `local`：每门指定窗口内的张数精确等于某个字符串，窗口外不限。例如窗口1—4、模式14/134/124、切1；反转单独显式选择。

“明显三色”提供明确版本：两门已包含相同三张顺子，第三门拥有对应三个点数的至少两个。计入自己的面子牌，仅为结构筛选，不猜意图，不检查这些牌是否还兼任其他用途。

`compare` 同时返回总行为频数和 A/B 两类合法候选同时存在的机会分母，以及 A/B/both/其他选择。一个状态有多个同类候选也只算一次机会。不同局数/对局数另列，同局样本不独立。柱形点击只筛实例，保持原集合分母。

完整比较示例见 `examples/follow-vs-terminal.json`。统计返回完整性标记、来源哈希、查询哈希、显式规则版本和样本ID；超时返回错误，不把扫描前缀或第一页冒充全量结果。

## 只读 HTTP 与 MCP

```text
GET  /api/research/schema
GET  /api/research/search?hand=233m&discard=2m
GET  /api/research/stats?shanten_basis=initial&shanten=4&seat_wind=0&turn_max=1
GET  /api/research/decisions/123
POST /api/research/compare    {filters,a,b}
```

查询参数见 `/api/research/schema`，数值字段也允许JSON整数。`metrics=0` 可只取记录和事实，不触发牌理。每页最多100条，统计不受分页影响。查询超时默认60秒，最多两项同时构造集合；不提供任意SQL接口。

LLM 可通过 stdio MCP 调用 `luckyj_schema/search/stats/decision/compare`。项目不绑定模型供应商，不收集模型API密钥。

```sh
python -m luckyj mcp --data /absolute/path/to/data
# 不方便设置工作目录的客户端可用：
python /absolute/path/to/LuckyJ/scripts/mcp_server.py --data /absolute/path/to/data
```

客户端配置样例见 `examples/mcp-config.json`，替换其中绝对路径。LLM 应先读定义，再生成统计配方；必须调用 stats/compare 对完整集合计算，不能用一页牌谱估计概率。存在未决指标或多重映射时应报告，不做虚假的唯一解释。
